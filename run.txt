# Meeting Write systemctl 실행법

## 서비스 시작 및 자동 실행 등록

```bash
systemctl --user daemon-reload
systemctl --user enable --now meeting-write-backend.service meeting-write-frontend.service
```

## 서비스 재시작

```bash
systemctl --user restart meeting-write-backend.service meeting-write-frontend.service
```

## 서비스 중지

```bash
systemctl --user stop meeting-write-backend.service meeting-write-frontend.service
```

## 상태 확인

```bash
systemctl --user status meeting-write-backend.service meeting-write-frontend.service
```

## 로그 확인

```bash
journalctl --user -u meeting-write-backend.service -f
journalctl --user -u meeting-write-frontend.service -f
```

## 재부팅 후 자동 실행 확인

```bash
loginctl show-user wia | grep Linger
```

`Linger=yes`가 아니면 아래 명령을 한 번 실행한다.

```bash
sudo loginctl enable-linger wia
```


## 자동 정리 스케줄

백엔드 서비스가 실행 중이면 매일 한국시간 05:00에 아래 정리를 자동 수행한다.

- `.jobs_work` 임시 작업 폴더 정리
- `recording_drafts.created_at` 기준 7일이 지난 보관 녹음 파일 삭제
- 만료된 보관 녹음의 `recording_drafts` Row 삭제
- 12시간이 지난 로그인 세션과 `auth_sessions` Row 삭제

스케줄 로직은 `meeting-write-backend.service` 안에서 실행되므로 별도 cron 등록은 필요 없다. 변경 사항 반영은 아래 재시작 명령을 사용한다.

```bash
systemctl --user restart meeting-write-backend.service meeting-write-frontend.service
```


## 분석·업로드 정책 설정

운영 정책은 프로젝트 루트의 `config/limits.yaml`에서 관리한다.

- 오디오 최대 크기·길이와 허용 확장자
- 참고자료 개수·개별/전체 크기와 허용 확장자
- PDF 페이지, PPTX 압축 해제, 문서 처리 timeout
- GPU/LLM worker와 전체/사용자별 작업 제한
- LLM timeout과 재시도 정책
- 작업 상태는 `backend/app.db`의 `processing_jobs`에 저장되며 백엔드 재시작 후 복구
- LLM 호출 메타데이터는 `backend/logs/llm_calls.jsonl`에 기록하며 프롬프트와 회의 내용은 제외

다른 설정 파일을 사용하려면 서비스 환경변수에 경로를 지정한다.

```ini
Environment=WIAMEET_CONFIG_PATH=config/limits.yaml
```

YAML의 알 수 없는 키, 누락된 필드, 잘못된 타입이나 범위는 백엔드 시작 시 오류로 처리된다. 값을 변경한 뒤에는 백엔드를 재시작한다.

```bash
systemctl --user restart meeting-write-backend.service
```

## Confluence Access Token 암호화

Confluence Access Token은 DB의 `confluence_settings.token_encrypted` 컬럼에 Fernet 방식으로 암호화되어 저장된다.

기본값은 백엔드 시작 시 `backend/.secrets/confluence_fernet.key` 키 파일을 자동 생성해 사용한다. 운영 환경에서 고정 키를 직접 지정하려면 `meeting-write-backend.service`에 아래 환경변수를 설정한다.

```ini
Environment=WIAMEET_CONFLUENCE_SECRET_KEY=Fernet키값
```

키가 바뀌면 기존 Access Token은 복호화할 수 없으므로, 키 파일과 환경변수는 백업/변경에 주의한다.
